# Project agent memory

Project-intrinsic notes that should travel with the code. README.md covers what
the project is and DATA-PLAN.md is the data contract; neither is repeated here.

## Sharp edges

- **The frozen corpus is not reproducible from `src/merge.py` at head.**
  `data/private/questions.jsonl` holds 1,451 labelled rows and was frozen before
  the Q-prefix duplicate collapsing landed; re-running the merge now yields
  1,525. Every accuracy number in README.md and RESULTS.md is quoted against the
  frozen file, so do not regenerate it without also regenerating the split, both
  models and RESULTS.md, and updating the numbers everywhere.
- **A model outlives its split, and that is how a fake accuracy happens.** A
  classifier trained on an earlier split scores far too well on a later one,
  because rows that were training data have become test data. Retrain after any
  change to `src/split.py`, its seed, or the corpus.
  `tools/report_results.py` reads both approaches from the run ledger in
  `data/private/runs/` (see `src/runs.py`), and every record carries the
  sha256 of the `test.jsonl` it was scored against; records against any other
  split are ignored. So a "not measurable" row in RESULTS.md means the ledger
  has no runs for the current split, and
  `python3 tools/compare_runs.py seeds --record` is what puts them back
  (about fifteen minutes per transformer seed on an M3 Pro).
- **The comparison is only symmetric while both approaches go through the
  ledger.** Both headline numbers are means over the same three seeds under the
  same procedure, timed on the same machine, and RESULTS.md's verdict paragraph
  is chosen by a fixed rule in `tools/report_results.py`. Do not paste a number
  measured any other way beside them.
- **The ledger holds two kinds of run, and the fraction is what keeps them
  apart.** Every record carries the fraction of the training pool it saw;
  `runs.load_runs` returns whole-data runs unless asked for another fraction, so
  the learning-curve points in `tools/learning_curve.py` cannot drift into
  RESULTS.md. LEARNING-CURVE.md is generated by
  `tools/report_learning_curve.py` from those records, its shape verdict chosen
  by a fixed rule there, and it shares the hash guard above.
- **The page reader is one rule with two sources of lines, and that is the
  invariant to protect.** `src/question_rule.py` is the whole algorithm;
  `src/page_lines.py` (text layer, points) and `src/page_ocr.py` (docTR,
  pixels) only feed it. It is the scout baseline unchanged, and its port is
  byte-identical to the prototype on all four public papers. It scores 43/43
  questions, 0 spurious, 43/43 exact page sets. Do not tune it against a paper
  that is not in a truth file, and do not fork it per source: two rules would
  be two sets of failures.
- **A single accuracy number for the reader is a lie.** `tools/score_reader.py`
  reports `found`, `spurious` and `exact pages` separately because they fail
  differently, and the one that matters is the last: a reader that finds every
  question but mis-cuts every page break looks excellent. Report all three.
- **What makes the permissive marker pattern safe is the two guards, not the
  regex.** `12 cm` inside a question matches the pattern; it dies because it is
  indented (the question column, learnt per document as the smallest x0 three
  body lines share) and because the numbers must ascend. A rule that instead
  insists on `\d+\.` finds *nothing* on a real exam paper - SEAB separates the
  number with a tab, Cambridge with a single space. `src/extract_pdf.py` uses
  that stricter pattern; it is right for the tutorial PDFs it was written for
  and wrong for exam papers.
- **The rung is chosen per paper, never per page.** Rung 1 works in points and
  rung 2 in pixels, so a document whose lines came from both has no single
  question column and the rule finds nothing. A paper goes to OCR when more
  than half its pages carry under 40 characters. Measured margin on the public
  papers: the emptiest real page has 344 characters and a rasterised page has
  0, so no individual page is ever a close call.
- **Two things about the reader look like bugs and are not.** A marker that is
  the first thing on its page cuts at the *page top*, not at the marker,
  because a tall display integral has glyphs above its own question number;
  removing that one line costs two exact page sets on the held-out paper. And
  `skewed_column()` fits the column as a line in (y, x) rather than a constant,
  because 0.7 degrees of scanner skew drifts the left edge ~28 px over a page;
  without it the skewed proxy scores 3/11, with it 11/11, and on a straight
  page the fitted slope comes back near zero so it costs nothing.
- **The public exam papers are not committed, so paper-backed tests skip by
  default.** They are third-party copyright and this repo is public. Only the
  labelling is committed (`tests/fixtures/*_truth.json`, question numbers and
  page indices, no question text). Put the PDFs in `tests/fixtures/papers/` or
  point `SORTED_PUBLIC_PAPERS` at them; see `tests/public_papers.py`. A green
  run that says "6 skipped" has not tested the reader against a real paper.
- **CIE 9709/32 is held out and is scored, never tuned against.** It was
  labelled only after the rule was frozen, which is the only reason its 11/11
  means anything. Do not look at it while changing the rule.
- `tools/measure_grouping_key_impact.py` needs `data/private/school_aliases.json`
  to report the school residual. Absent, that section is a no-op rather than an
  error, so a zero there can mean "no alias map" rather than "no residual".

## Running things

- Tests use synthetic fixtures only: `python3 -m pytest` needs no private data.
- **Anything that trains needs the framework interpreter, not the one on PATH.**
  scikit-learn and torch are installed for
  `/Library/Frameworks/Python.framework/Versions/3.13/bin/python3`; the
  Homebrew `python3` that PATH resolves first has neither, so a training run
  started as plain `python3` dies on `ModuleNotFoundError: sklearn` before it
  reaches the ledger. The tests pass under either.
- **The reader's OCR path is a separate Python 3.12 environment, and its
  absence is not an error.** `pip install -r requirements.txt` gets rung 1;
  rung 2 needs `requirements-ocr.txt` in its own venv
  (`uv venv --python 3.12 .venv-ocr`). Every one of those imports is deferred
  behind `page_ocr._import_doctr`, so a text-layer-only install works and a
  missing stack reports what to install rather than a bare
  `ModuleNotFoundError`. The traps, in the order they bite: the system Python
  is too new (nothing here has 3.14 wheels, so `uv python install 3.12` first);
  `python-doctr[torch]` warns that the extra no longer exists, which is safe to
  ignore; keep this venv separate from any paddle or surya environment, because
  they disagree about numpy. docTR downloads its weights on first use.
- `conftest.py` at the root is the one import shim. Modules import their
  siblings by bare name because they run as `python3 src/x.py`; tools do their
  own explicit insert. Do not add per-file `sys.path` blocks.
- Every writer goes through `assert_inside_project` in `src/paths.py`, and the
  two source roots are overridable with `EMBER_SOURCE_ROOT` and `TRIPLEMATH_PDF`.
